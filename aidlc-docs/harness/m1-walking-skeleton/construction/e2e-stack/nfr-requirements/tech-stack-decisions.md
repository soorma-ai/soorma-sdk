# Tech Stack Decisions — U2 `e2e-stack`

Every choice below is **technology** under `prd-gap-classification.md` (no PRD or the contract
makes it; I11 places it here). Answers: U2-NFR-Q1 to Q6 (audit 2026-11-18T20:01:38Z). Inherited
from U1 unchanged: TS-U1-01 (Node 24), -02 (pnpm, one workspace), -03 (TypeScript by type
stripping), -05 (`ajv` 2020-12), -06 (`yaml`), -09 (Vitest), -12 (CI rules).

| Id | Decision | Rationale | Rejected alternative |
|---|---|---|---|
| TS-U2-01 | **TypeScript on this repository's Node 24**, a private workspace package `e2e/` beside `conformance/` and `tools/`; each command a module and a `pnpm` script | One toolchain and lock file; U1's contract readers reused; every command testable by Vitest (Q1 A) | Shell with `curl` and `jq`: credentials on command lines or in header files; no schema validation without another tool (Q1 B) |
| TS-U2-02 | **`core-up --core-node <path>`** for soorma-core's Node; refused unless its version equals the clone's `.node-version` and this repository's pnpm equals the clone's `packageManager`; soorma-core's steps run with that Node first on their `PATH`. **CI**: `actions/setup-node` for `26.13.0` first (its path kept as a step output), then for `.node-version` last | Exact toolchain for soorma-core without a container; a path is not a secret, so an argument (Q2 A) | A container with the Docker socket mounted (Q2 B); downloading Node in `core-up` (Q2 C) |
| TS-U2-03 | **`node:https`** for every raw call: the clone's CA as the only `ca`, `agent: false`, `Soorma-Contract-Version: 0.1.0`; request bodies written by the code, never read from a file | As soorma-core's `stack-client.ts`; no HTTP client dependency; exact control of what is sent | An HTTP client library: a dependency for four kinds of call |
| TS-U2-04 | **`ajv` 2020-12 with `yaml`**: PS-02's response check and TC-ES-020's fake validate against the operation's schema resolved from the vendored OpenAPI documents (U1's contract reader, `conformance/runner/src/contract.ts`, reused) | One way to read the contract in the repository | A second schema reader in `e2e/` |
| TS-U2-05 | **LS-01 reads `credentials.md` as text**: every `` `soorma_[a-z0-9]+_` `` it names, with the kind from the same table row or sentence. A test pins the parse of the vendored file (the six prefixes at the tag) | The prefixes stay the contract's; the test catches a change in the file's shape | A list in code (the user: never a copy) |
| TS-U2-06 | **K**: 32 bytes from `node:crypto`'s `randomBytes`, base64url (43 characters) | Inside S1's policy (8 to 256 code points); never reused | A fixed or derived secret |
| TS-U2-07 | **`docker` and `git` through `execFile`** (no shell), arguments as arrays; no secret ever in an argument or the child's environment. Detection: `docker version`, `docker compose version`, `docker compose ls --all`, `docker volume ls --filter label=com.docker.compose.project=soorma-local`; clone: `git clone --depth 1 --branch <tag>`, `git rev-parse HEAD` | No shell interpolation; the user's rule on secrets | A shell script per step |
| TS-U2-08 | **The `changes` job copies soorma-core's #26 job**: full-history checkout without credentials, then shell and `git diff --name-only --no-renames <base> <head>`; the base is the PR's base SHA or the push's `before`, passed through `env`; any failure, a zero SHA or an empty diff runs the end-to-end job | Proven in soorma-core; no third-party paths-filter action holding the decision | `dorny/paths-filter` or similar: one more pinned dependency for a few lines of git |
| TS-U2-09 | **Tests**: Vitest. The fake S1 and S2 is a `node:https` server with a per-test CA made by U1's CA maker (system `openssl`, `conformance/runner/src/rundir.ts`), stateful for the end semantics; fake `docker` and `git` are small Node scripts in `e2e/test-fixtures/`, put first on `PATH` | Q4 A; no new dependency | Mocking `node:https` or `execFile` in-process: would not test the real call paths |
| TS-U2-10 | **No new npm dependency** in U2 | NFR-U2-18 | — |
| TS-U2-11 | **Time limits** (the user, 2026-11-18T20:54:18Z): **raw call** (each `setup` and `prove-stack` request, connecting through the whole response): **30 s**. **Child steps**: `git clone --depth 1`: **3 min**; `pnpm install --frozen-lockfile` (the clone): **6 min**; `docker build`, **per image**: **5 min**; `pnpm stack:init`: **2 min**; `pnpm stack:up`: **5 min**; `docker compose logs`, **per service**: **1 min**; `docker compose down -v`: **3 min**; every other child command (`docker version`, `docker compose version`, `docker compose ls`, `docker volume ls`, `git rev-parse`, `--core-node --version`, `pnpm --version`): **30 s**. A child that runs out is sent `SIGTERM`, then `SIGKILL` after 10 s | Each well under the job's 20 minutes; each several times its step's normal time at the tag (soorma-core run 43391996560: S1 image 28 s, the others about 6 s, `stack:init` 1 s, `stack:up` 20 s), so a slow runner passes and a hung one fails in minutes. One step hanging after the others' normal time ends `core-up` in about 10 minutes | No limits, leaving the job's timeout to stop a hang (loses the step name and, read as `failure()`, the logs) |

## Jobs U2 Adds (shape, not YAML)

| Job | Runs | Fails when |
|---|---|---|
| `changes` | On `pull_request` and pushes to `dev`, never pushes to `main`. Outputs `e2e=false` only for a computable, non-empty, `aidlc-docs/`-only diff | The diff step errors in a way the shell does not catch (the dependent job is then skipped and the workflow fails) |
| `e2e` | `needs: changes`, `if: needs.changes.outputs.e2e == 'true'`; `ubuntu-24.04`; `timeout-minutes: 20` (a backstop: TS-U2-11's limits fire first); `contents: read`. Check out; set up pnpm; Node 26.13.0 then Node 24; install this repository's workspace (frozen); `core-up --core-node <path>`; `setup --agents agent-a,agent-b`; `prove-stack`; then `core-down`, **`if: always()`**, with **`--logs` when `failure() \|\| cancelled()`** | Any command exits non-zero; a time limit runs out; the 20-minute timeout |
| `unit` (U1's, extended) | Also Vitest for `e2e/` (TC-ES-002, 003, 013 to 023; TC-ES-008's workflow-condition test) | Any test fails |

U1's workflow check covers both new jobs (SHA pins, runner, permissions, no `.e2e/` upload).
