# Tech Stack Decisions — U4 `python-harness`

Every choice below is **technology** under `prd-gap-classification.md`: no PRD and no part of the
contract makes it, and I11 places it here. Answers: U4-NFR-Q1 to Q9 (audit).

**Inherited unchanged**: U1's repository rules (TS-U1-12: workflows on `ubuntu-24.04`, actions
pinned by SHA, `contents: read`; the 7-day cooldown; Dependabot into `dev`; dependency review;
SPDX); the repository's Node tooling for the runner, the stub, the checks and the generators;
U3's OpenTelemetry semantic conventions 1.45.0.

| Id | Decision | Rationale | Rejected alternative |
|---|---|---|---|
| TS-U4-01 | **The package at `python/`**, its own `uv` project (`pyproject.toml`, `uv.lock`), `src/` layout: `python/src/soorma/`. The driver (`python/conformance_driver/`), the example (`python/examples/two_agents/`) and the end-to-end test (`python/e2e/`) live beside it, outside the distribution | U4-NFR-Q4 A; the repository layout leaves room per language (D-04) | Putting Python in the pnpm workspace (it has no Python ecosystem) |
| TS-U4-02 | **Python 3.11 and 3.15**: `requires-python = ">=3.11"`; CI on 3.11 (3.11.18) and 3.15 (3.15.2, 2026-10-25), exact patch versions pinned in the workflow | NFR-08; measured: 3.15 newest stable, 3.11 the floor until 2027-10 | Testing 3.11 to 3.15 every version (four stacks of cost for no case the ends miss) |
| TS-U4-03 | **`uv`** at an exact version (the newest past the cooldown, picked at Code Generation and named in `DEPENDENCIES.md`), installed in CI by the pinned `setup-uv` action; `uv sync --locked`; **`exclude-newer`** for the cooldown; **`no-build`** (wheels only) for dependencies | U4-NFR-Q4 A; NFR-U1-24's lock discipline for Python; no third-party build code at install, as U1 refuses install scripts | `pip` with `pip-tools` and hashed requirement files |
| TS-U4-04 | **`uv_build`** at an exact version as the build backend; the wheel and sdist exclude `soorma/_internal/` (the values hook) through the backend's exclude settings, and `package-python` proves it | U4-NFR-Q4 A; a pure-Python package needs nothing more | `hatchling`, `setuptools` (more configuration for the same output) |
| TS-U4-05 | **The HTTP client: the standard library** (`asyncio.open_connection` with an `ssl.SSLContext`), **with the SDK's own strict, bounded, sans-IO response parser** (`_http.py`), one connection per request. **Chosen over `h11`**, which the user allowed: the contract's HTTP is a narrow subset (four `POST` endpoints; responses with `Content-Length`, chunked, or `text/event-stream`), so the parser is small, about 300 lines with its limits. Owning it lets every one of the user's conditions hold exactly as written: CRLF only and no obs-fold; per-line, header-count, head, body, chunk-line and trailer bounds; `Content-Length` with `Transfer-Encoding` refused; a `TransportError` reason for each failure, never the bytes. `h11` would add a runtime dependency and an event model to map, and some conditions would be enforced around it rather than by it (its limit is one incomplete-event size, not per-line and per-count bounds). The parser's risk is paid for with table-driven tests of malformed input and a seeded fuzz test (NFR-U4-07 to -11) | U4-NFR-Q2 A with the user's conditions; FWD-02's byte-for-byte splice needs exact control of what is written; no runtime dependency, as U3's `node:https` | `h11` (acceptable to the user; a dependency, and the conditions partly outside it); `httpx`; `aiohttp` |
| TS-U4-06 | **The fuzz test uses the standard library** (`random` with fixed seeds): random bytes and mutations of valid responses (truncation, flips, duplicated and oversized lines), fed in random splits; every input must end in a response or `TransportError` | The user's condition (a property or fuzz test); reproducible, no `hypothesis` dependency | `hypothesis` (a development dependency for one property) |
| TS-U4-07 | **The trust store**: `ssl.create_default_context()` plus `load_verify_locations(ca_file)`; `check_hostname` on, `minimum_version` TLS 1.2; read once per client at `start()`. A verification failure's `TransportError` (`tls`) hints at python.org's *Install Certificates* step when the default store loaded no CA, never naming a certificate | U4-NFR-Q3 A with the user's condition; measured 128 to 186 OS CAs on every local interpreter | `certifi` (a bundle updated only by upgrading); `truststore` (wraps `ssl`) |
| TS-U4-08 | **`opentelemetry-api`**, a range `>= floor, < 2`; the floor picked at Code Generation (the oldest 1.x with non-recording spans, remote `SpanContext`, links and `set_span_in_context`, and 3.11 wheels); the lock at the newest past the cooldown; CI once at the floor, from the lock | U4-NFR-Q6 A; one API in the tenant's environment | An exact version (fights the tenant's install) |
| TS-U4-09 | **Semantic conventions 1.45.0** as constants in `_tracing.py`; `messaging.system` `soorma` | As TS-U3-07 | `opentelemetry-semantic-conventions` |
| TS-U4-10 | **C-10 by `python/scripts/generate.ts`**, run with the repository's Node: it reads the vendored JSON schemas and writes `python/src/soorma/_generated/` as `TypedDict` modules (agent side; every envelope member optional); listed in `tools/generated-types/packages.json`, so the existing `checks` job runs it | U4-NFR-Q7 A; one generator toolchain beside U3's (`typescript/scripts/generate.ts`), reading the same vendored schemas | A Python generator; `datamodel-code-generator` |
| TS-U4-11 | **Development tools**: `pytest`, `pytest-asyncio`, `ruff` (lint and format), `mypy --strict`, `pip-audit`; exact versions in the lock's development group. Tests run with warnings as errors and a loop exception handler that fails a test on any unretrieved task exception | U4-NFR-Q5 A, Q9 A | `unittest` only (no static check of the public types) |
| TS-U4-12 | **Randomness and identifiers**: `uuid.uuid4()` for `new_instance_id`; `secrets.token_bytes` for generated trace and span ids | CFG-06; TRC-03 | `random` |
| TS-U4-13 | **Clocks**: `_clock.py` only; `wall_now()` calls `time.time()` at each read, `mono_now()` calls `time.monotonic()`; timers are the running loop's; the import-binding check (PH-CLK-02) | PH-CLK-01, 02; REN-07; CDI-06 | `datetime.now`; a function bound at import (the patched clock would never reach the SDK) |
| TS-U4-14 | **The named values** in `_limits.py`: as U3's, with **`D_lang` 256** | U4-NFR-Q1 A; measured 3.11 depths | Options a tenant sets |
| TS-U4-15 | **The warning**: `SoormaWarning(UserWarning)` emitted by `warnings.warn_explicit` with a fresh registry per lineage, inside a guard that swallows any exception from the emit (never `asyncio.CancelledError`) | PH-REN-03, 04 | `logging` (the SDK writes no log) |
| TS-U4-16 | **No logger, no environment variable, no host read** in the package: `ruff`'s banned-API rules refuse `os.environ`, `os.getenv`, `socket.gethostname`, `platform.node` and `print` in `python/src/soorma/` | CFG-05, CFG-07; NFR-06; PH-API-05 | Review only |
